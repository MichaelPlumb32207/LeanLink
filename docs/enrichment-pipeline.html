LeanLink Enrichment & Inference Pipeline

Research-only POC · Florida NPA voters · OSINT + Grok live search · Last updated 2026-06-27

Research posture: Output informs a UF political-science professor's research, courses, and publications. Not for contacting, marketing, or targeting individuals. Enrichment is OSINT-only (no data brokers).

3. Enrichment — Grok live search (v1)

Decision D-008 Start with Grok web_search via xAI Responses API (POST /v1/responses). Evaluate via dashboard Test enrichment before building modular fetchers.

OSINT flow per voter

  1. Build EnrichmentBundle (anchor + contact flags + history context).
  2. Grok searches public web/social for matching persona(s) in Florida.
  3. Returns structured JSON: matches, signals, resolution status, lean, confidence, evidence.
  4. Code guardrails enforce policy (below).

5. Opposition mobilization (deterministic)

North = Left, South = Right. Measures likelihood a voter mobilizes against a ballot/contact scenario.

opposition_score = round(turnout_score × (confidence / 100) × oppositionFactor(lean, ballot_favors))

8. How to evaluate

  1. Set XAI_API_KEY (and optional XAI_MODEL=grok-4.3) in env.
  2. Select an upload in the dashboard → Test enrichment (pick row index).
  3. Inspect JSON: bundle, debug.prompt_user, result.enrichment.citations, guardrailed lean/confidence.
  4. When satisfied, Run Analysis Job for full batch (slower — one Grok call per voter).

9. Fallback behavior

  • No XAI_API_KEY → deterministic mock lean (pipeline still runs).
  • Grok API error on a row → mock fallback + error noted in evidence; row still completes.
  • Export CSV remains hash-only (no names) — safe for sharing.
