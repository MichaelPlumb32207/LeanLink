LeanLink Enrichment & Inference Pipeline

Voter lean intelligence · Florida NPAs · Validated on Calhoun (736) + Alachua (40,546) · Last updated 2026-07-05

Product layer — tiered / prepaid / waterfall (D-024 · D-026). The enrichment arms below sit inside a productized flow:
  • Generic client intake — accept an arbitrary voter list (CSV/paste/JSON, name + one of county/ZIP/address), normalized into the same record shape the arms consume, billed to the client's prepaid account.
  • Waterfall settlement — a voter settles once fusion yields a non-Undetermined lean at confidence ≥ 60, at the cheapest contributing tier; the settle fee is billed once ever, and later, pricier arms skip settled voters by default.
  • Confirmed pricing (D-026) — $2,500 initiation (once per account, ever) · $0.03/record baseline · per settled lean $0.15 (Tier 1 FEC) / $0.25 (Tier 2 FL contrib + Sunbiz) / $0.33 + $0.05 per attempt (Tier 3 OSINT).
  • Researcher review — settlement (billing) and research continuation are separate switches: Accept freezes a voter's fused lean and excludes them from all arms; Reopen clears it; Re-enroll (per voter or cohort) pushes settled voters back into later arms without re-billing. The dashboard waterfall-gate strip shows eligible-remaining, accepted/re-enrolled counts, and projected max next-arm spend before advancing a tier.
  • Client deliverable — the client's original file back with Lean / Confidence / Source (all contributing arms, settled arm first) / Status (accepted · fused · provisional · conflicted · unresearched) / Evidence columns. Lean is resolved under lean_precedence (D-044: default wallet when party and public-evidence disagree; presentation only). ?format=audit is operator-internal (D-042 layer 4).
  • Resilience — FEC lookups retry transient 5xx in-call, and a background cron re-attempts anything that still failed.
Authoritative detail: docs/PROGRESS.md, docs/CLAUDE.md, docs/DECISIONS.md D-024 → D-028.

1. Ingest filter (what “NPA + ACT” means)

Not “politically active voters.” ACT is the Florida DOS registration status code on field 28 of the voter extract: ACT = active on the rolls, INA = inactive. Default ingest keeps NPA (no party affiliation) + ACT only, plus excludes suppressed / public-records-exempt rows (DEFAULT_LEANLINK_FILTER in lib/fl-voter-registration.ts).

That filtered set is the working upload — typically hundreds to tens of thousands per county, not the full raw extract.

This filter applies to FL-extract uploads (research track). Client-supplied lists enter through generic intake instead — anchor gate is name + one of county/ZIP/address; no NPA/ACT filter.

2. Product tiers

Confirmed client pricing (D-026): $2,500 initiation (once per account, ever) + $0.03/record baseline at intake + a per-lean settle fee at the tier that settled the voter. A voter settles once fusion yields a non-Undetermined lean at confidence ≥ 60, at the cheapest contributing tier — billed once ever. FL-extract (research-track) uploads are never billed.

TierArmsClient feeScope
Baseline Intake · anchor/household · fusion · deliverable $0.03 / record Every accepted record
Tier 1 — FEC Local FEC bulk index (primary, D-028) · throttled Open API (fallback) $0.15 / settled lean Whole upload (local SQL match)
Tier 2 — FL contrib + Sunbiz FL contrib index (layer 1 person + layer 2 entity) · Sunbiz officer bridge $0.25 / settled lean Unsettled remainder (free pass)
Tier 3 — OSINT grok-full / apify-modular / scorecard $0.33 / settled lean + $0.05 / attempt Opt-in unsettled remainder (D-020)

Tiers 1–2 match against local bulk indexes — No per-voter API fees (the fee prices the research, not third-party compute). Tier 3 carries real per-attempt API cost (~$0.03/voter Grok), which is why attempts are billed.

8. Guardrails

  • D-013: Identity separate from lean
  • D-016: Lean requires ideological signals[] in matches
  • D-010: No race/gender in prompts or logic
  • D-026: Researcher Accept freezes a voter's fused lean — deliverable values never drift after acceptance
  • D-027: FL-extract data research-only + structurally unbillable (migration 012 CHECK); OSINT-only / no data brokers on both tracks
  • Layer 2 entity donations: lower fusion weight than direct person FEC/FL hits
