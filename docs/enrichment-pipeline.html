LeanLink Enrichment & Inference Pipeline

Research-only POC · Florida NPA voters · Multi-arm evidence accumulator · Last updated 2026-06-29

Research posture: Output informs a UF political-science professor's research, courses, and publications. Not for contacting, marketing, or targeting individuals. Enrichment is OSINT-only (no data brokers).

1. Pipeline overview

Target architecture (D-023): Upload ingests NPA subset. Evidence arms (FEC, OSINT, media, civic, household — pluggable via lib/evidence/arms.ts) each: retrieve → identity gate → lean signal → append evidence_events. Fusion writes voter_lean_fusion and lean_results with audit trail. Dashboard Evidence accumulator shows upload command bar + split-pane voter timeline. Research lab (subset tests) remains for POC validation. Full-file Grok batch disabled unless LEANLINK_ENABLE_BATCH_INFERENCE=true (D-020). Pitch: evidence-accumulator-pitch.html.

Query plan (all modes)

Social first → contact → Tier-A lean (donations/FEC, local media, civic filings) → directory last. See lib/enrichment/query-builder.ts.

OSINT flow per voter

  1. Build EnrichmentBundle (anchor + contact + email_insights + history).
  2. Run selected mode (Grok search and/or Apify fetch + optional Street View context).
  3. Grok returns structured JSON: identity_matches, signals[], lean, confidence.
  4. applyInferenceGuardrails — lean requires non-empty ideological signals[] (D-016).

FEC contributor lookup (D-021)

Deterministic Direct FEC Open API Schedule A search by contributor name + FL state/city/zip. No Grok. Whole-file sweep + per-row identity scoring (lib/fec/identity-match.ts, donation-lean.ts). Calhoun: 27 raw → 3 confirmed. Grok site:fec.gov queries remain indirect and poor yield vs direct API.

Evidence accumulator (D-023)

Ledger Each arm appends evidence_events with identity band, lean signal, evidence strings, URLs, cost. fuseEvidenceEvents merges into voter_lean_fusion and lean_results. Arm registry: lib/evidence/arms.ts. APIs: GET .../evidence-summary, GET/POST .../evidence. UI: components/evidence-workspace.tsx.

Street View (research arm — D-018)

Separate Dashboard exposes exploratory only (visible-cue heuristics for professor field validation). API still supports strict (signage only). lean_street_view is not merged into main OSINT lean.

5. Opposition mobilization (deterministic)

North = Left, South = Right. Measures likelihood a voter mobilizes against a ballot/contact scenario.

opposition_score = round(turnout_score × (confidence / 100) × oppositionFactor(lean, ballot_favors))

8. How to evaluate

  1. Env: XAI_API_KEY for Grok tests; optional APIFY_API_TOKEN, GOOGLE_MAPS_API_KEY, FEC_API_KEY (FEC falls back to DEMO_KEY).
  2. Upload county file → confirm ingest count (no AI spend).
  3. Dashboard → select upload → Analyze: confirm row subset, pick test, run.
  4. Run FEC contributor lookup first on subset ($0) — record rows_with_hits.
  5. Run scorecard or test enrichment per mode; refresh docs/COST-ESTIMATES.md.
  6. Try apify-modular; inspect apify_runs, pipeline_steps, GET /api/enrichment/apify-config.
  7. Full county batch only after explicit LEANLINK_ENABLE_BATCH_INFERENCE=true + budget sign-off.

9. Fallback behavior

  • No XAI_API_KEY → deterministic mock lean (pipeline still runs).
  • Grok API error on a row → mock fallback + error noted in evidence; row still completes.
  • Export CSV remains hash-only (no names) — safe for sharing.
